Only on days with real numbers

The notes must contain a table or a run of figures. If the model has to invent numbers to illustrate, they are labelled "Example data" on the card, and that day gets no question about them.

Teach before testing

"The numbers" sits inside the lesson, after How it works, so the data is evidence for the idea just explained. No data question comes before the learner has seen that page.

Easy to hard

Reading a value (~25% into practice) comes before applying a rule (~60%). Building a graph, the hardest, sits in the second half. Never in the pre-test, never the first question.

Two at most, spaced out

At most two data questions a session, at least three cards apart. They count toward the picture budget (25% of cards), so a data day draws fewer other pictures.

Not on maths or history days

Maths stays about 80% solving (invariant 1). History keeps its timelines. Science, economics, geography, psychology and computing get these.

They come back

A missed data question goes into spaced review like any other, and its walkthrough lights the row or cell that held the answer.

1 · Inside the lesson

The numbers

A page in the lesson card, between How it works and Core concepts. It opens with one sentence saying what the numbers show, then the data, then the one thing to notice.

It opens on the chart when the data has a trend, because a shape is quicker to read than a column. It opens on the table when the data is a list to look things up in. Chart | Table switches between them; the thumb slides on a spring and the view slides the same way it is going.

The line draws itself once, left to right, the first time the page is seen. The point that matters is labelled with its value.

When

  • Lesson page 3 of 5 on any non-maths day with figures in the notes
  • One page per day, never more; a day without numbers simply has no such page
  • The same figure returns under a missed data question, as "Look at it again"

Try: switch Chart and Table. Swipe the table sideways at phone width.

2 · The pictures

Four new charts, all drawn by code

Each takes numbers and nothing else. It refuses to draw when the numbers can't make an honest picture: a pie that doesn't add up, a trend from two points, a scatter with no spread. Every chart turns into its table and back. Labels sit on the lines instead of in a legend, so nobody matches colours.

Two lines. Sun plant against shade plant. Used when the notes compare two things over the same range. Science, geography.

Grouped bars. Two cities, four months. Bars always start at zero. Geography, economics.

Donut. Only for parts of one whole, six slices at most, and code checks they add to 100%. Names sit in a list beside it, so a thin slice never loses its label.

Scatter with a trend line. The line is calculated from the dots, never drawn by the model, and the card says a pattern is not proof. Psychology, science.

3 · Question

Read the table

Questions that are answered by looking things up: which row is biggest, what changed between two rows, where a value crosses a line. The code works out the right answer from the table itself, so a slip in the model's key can't mark a learner wrong.

After the answer, the evidence lights up. A "Rise" column slides in beside the data, the rows that prove it stay bright, and everything else steps back.

When

  • About a quarter of the way through practice, after a warm-up question
  • Uses the same data as the lesson's "The numbers" page, so it checks what was just taught
  • The first data question of the day, because looking up is the easiest data skill

Try: pick a wrong answer first; the card shows you why. Reset and pick the right one.

4 · Question

Complete the table

A few cells are blank and follow a rule written above the table. The first row is done as an example. The learner types numbers (a number keyboard on a phone) and Enter moves to the next blank.

The code checks each cell with a little leeway, so 1.5 and 1.50 both count. A wrong cell keeps what was typed, crossed out, with the right number written under it. The mistake is fixed where it was made instead of being explained somewhere else.

When

  • Around 60% through practice, after the learner has read the data once
  • Only when the columns are linked by a rule (totals, prices per item, percentages, speed = distance ÷ time)
  • Economics and science most of all; geography for density or percentage tables

Try: type 1.5 and 1.3, then Check.

5 · Question

Spot the bad graph

A chart that is true but misleading: an axis that starts at 95, a squashed scale, a pie that adds to 130%. The learner says what is wrong with it.

Then the card fixes the graph in front of them. The axis slides down to zero on a spring and the "soaring" bars settle to nearly equal. Seeing the same numbers tell a different story is what makes it stick.

When

  • Late in practice, once honest charts have been seen earlier that day
  • Only on days about statistics, data, advertising or economics, and at most once every few days
  • Built by code from the day's own numbers with one known distortion, so the answer is never a guess

Try: answer, then watch the axis.

6 · Question · the stretch goal

Build the graph

The learner makes the picture instead of reading one. Tap the grid to place each point from the table; the point snaps to the nearest line and pops in. Drag a placed point to move it: it follows the finger exactly, and springs onto the grid when let go.

On Check, right points turn green. A wrong point shows a ring where it should be and glides there. Then the line draws itself through all of them, and the card says what the line means.

When

  • The second half of practice. It is the hardest data card, so it never comes first
  • Only when the data is pairs of numbers with a pattern, three to six points
  • Instead of Complete the table, not as well as it: two data questions a session at most

Try: place one point in the wrong spot on purpose, then Check.

7 · For teachers

What the teacher sees

The same cards work in assignments because the teacher builder shares the plan builder's question code. On the results page each data question shows the class's first-try score and the most common wrong answer, written out the way the students answered it.

That common wrong answer is often the lesson: here, most students who missed it divided the wrong way round.
